Visual Introduction

From a broken object to a segmentation problem

What is a 3D point cloud?

A 3D scanner does not produce a smooth surface — it produces a set of discrete points in space. Each point carries its coordinates (x, y, z) and a surface normal (the direction perpendicular to the surface at that location). Points are not connected to each other.

# One fragment = array of N points (x, y, z)
pts = [
  [ 0.12, -0.43, 0.87],  # point 0
  [ 0.15, -0.41, 0.85],  # point 1
                 # ... 4,998 more
  [ 0.31, 0.02, -0.11],  # point 4999
]  # shape: (5,000, 3)

An object can break into 2 to 20 fragments. Each fragment = 5,000 points in our pipeline.

Per-point label: fracture or intact?

When an object breaks, each fragment has two types of surfaces:

Label 1 — Fracture surface
Surface created by the break. Rough, irregular edge. This is where fragments will be reassembled. Rare: can represent only 2–3% of points.
Label 0 — Intact surface
Original surface of the object. Smooth, continuous. It existed before the break. Majority class: typically 90–98% of points.
The task: predict 0 or 1 for every point in the cloud. No 3D reconstruction — pure per-point binary classification.

Context

The question we set out to answer

Background

Object reassembly from 3D scans requires identifying, for each fragment, which surface was created by the fracture — as opposed to the original intact surface. This binary classification is a prerequisite for any downstream matching or assembly step.

The GARF baseline uses PointTransformerV3 (PTv3), a state-of-the-art 3D transformer — 12.7 M parameters, high accuracy, but computationally heavy.

Research question: Can a much lighter model (~500 K params) learn the same task, and where exactly does it succeed or fail compared to PTv3?

The goal was not just to build a smaller model, but to understand its behavior — quantitatively and geometrically.

Dataset — Breaking Bad

Categorieseveryday (plates, mugs, bowls…) + artifact
FormatHDF5 — 27 GB
Val set8,025 objects — 33,065 fragments
CNN sampling5,000 pts / fragment — constant resolution
GARF sampling5,000 pts / object total — shared budget
LabelBinary per point — fracture (1) / intact (0)

No official test split for the everyday category. Threshold calibrated on a val subset via sweep [0.30–0.80], frozen before evaluation.

Design rationale

3-view projectionAllows using standard 2D CNNs on unordered point clouds
Gaussian splattingSmooth, differentiable mapping from points to pixels
Geometric featuresLargest gain in ablation (+4–5 pp F1)
5,000 pts / fragmentConstant resolution regardless of object complexity — key difference vs GARF

The 2D projection choice is a deliberate trade-off: it makes the model light and simple, but introduces an inherent spatial resolution limit — one pixel covers a 3D region, not a point. This will matter later.

What the CNN sees: 8 image channels + global context

3D → 2D projection: 8 channels per image

Each fragment → 3 orthographic images 128×128 (XY, XZ, YZ). Multiple points per pixel → weighted average.

What F1 tells us

At 86.9%, the model correctly classifies the large majority of points. It has learned the fracture signal — where fracture zones tend to be on these objects. The ~4 pp gap with GARF is real but moderate for a 24× smaller model.

The FP rate dropped from 22.4% (Step 9) to 16.6% (Step 11) — the model predicts fracture more conservatively after fine-tuning.

By fragmentation complexity: the model performs better on objects with more fragments — likely because more-fragmented objects tend to have larger, more visible fracture areas.

What F1 does not tell us

F1 counts correctly classified points. It does not measure:

Boundary precisionIs the predicted fracture boundary sharp or diffuse?
Spatial continuityIs the predicted surface connected and smooth?
Fine structureAre thin ramified branches captured?
Geometric usabilityIs the prediction useful for pairwise fragment matching?
To answer these questions, we generated interactive 3D visualizations — and they revealed things that the numbers alone could not.

Where CNN wins: on highly fragmented objects (9 parts), GARF's fixed 5,000-point budget collapses to ~555 pts/fragment. At that resolution, thin fracture lines become invisible. The CNN, with 5,000 pts/fragment regardless of complexity, maintains its resolution.

Where CNN fails: on the mug (F1=0.305, recall=18.5%), the 3 fixed orthographic views cannot resolve a circular fracture on a cylindrical surface — the fracture collapses onto the intact surface in projection. This is a structural limitation of fixed orthographic views.

What the visualizations revealed

F1 is a starting point, not an answer

Findings from visual inspection

These observations would not have been possible from the F1 numbers alone.

Prediction is a zone, not a surface

The predicted fracture is often thicker and more spread than the real one. One pixel in a 64×64 projection covers a spatial region — the model predicts approximately where the fracture is, not its precise boundary.

FP on high-curvature intact zones

Bowl rims, plate edges, mug lips — these look like fractures in projection. They form coherent spatial regions, so post-processing (kNN vote, cluster removal) cannot distinguish them from real fractures. We confirmed ΔF1 ≈ 0 from post-processing.

Fine branches partially missed

Large, compact fracture zones are well detected. Fine ramified branches are partially missed. They represent few points — F1 barely changes — but they define the fracture shape and matter for reassembly matching.

Curved surfaces are a structural blind spot

The mug failure (recall = 18.5%) is not a training issue — it is a projection issue. A circular fracture on a cylinder is ambiguous in all three orthographic views simultaneously. The architecture cannot resolve this without additional viewpoints.

What this means for evaluation

F1 measures pointwise accuracy. For reassembly, what matters is whether the predicted surface is geometrically usable for pairwise fragment matching. These are different things.

Missing metricWhat it would capture
Boundary F1Precision on fracture boundary points only — penalizes diffusion
Hausdorff distanceMaximum geometric error between predicted and GT boundary
Chamfer distanceAverage spatial offset — penalizes systematic shift
Normal consistencyNormal alignment on predicted fracture — matters for fitting

Post-processing result

kNN majority vote and small cluster removal were tested and produced ΔF1 ≈ 0. This confirms that FP are not isolated noise — they are structurally coherent predictions that require a better loss function or architecture, not a filter.

The model has learned the signal of fracture segmentation. Whether it has learned the geometry is a question these visualizations helped us ask — and that the current metrics cannot yet answer.

Summary

What we know and where we go from here

What this study established

✓ A 24× lighter model reaches 86.9% F1 vs ~90.9% for PTv3 — the compression cost is moderate at the global level.
✓ On highly fragmented objects (9 parts), the CNN outperforms GARF (0.902 vs 0.673) — constant resolution per fragment is a real advantage when GARF's budget runs out.
✓ The low-ratio failure was diagnosable and partially fixable through Focal Loss + WeightedSampler (+13.4 pp on hard cases).
→ Visualizations revealed that F1 hides geometric imprecision: diffuse predictions, FP on curved intact zones, and a structural failure on cylindrical fractures.
→ Post-processing cannot fix these issues — they require changes at the loss or architecture level.

Concrete next steps

1. Add geometric metrics. Boundary F1 and Hausdorff distance should complement F1 to evaluate whether predictions are geometrically usable — not just statistically accurate.
2. Boundary-aware loss. A term that specifically penalizes errors on fracture boundaries would push toward sharper, more precise predictions.
3. Higher projection resolution. 64×64 → 128×128 halves spatial ambiguity per pixel. Direct reduction in prediction diffusion, no architectural change.
4. Adaptive viewpoints. Fixed orthographic projections fail on curved surfaces. Learned or surface-adapted viewpoints could fix the cylindrical fracture blind spot.
5. Zero-shot evaluation. Test on Fractura and Fantastic Breaks without recalibration — to measure how well the model generalizes beyond Breaking Bad.
Without the visualizations, we would not know why the model fails — only that it does. The next steps are concrete precisely because we looked beyond the numbers.
